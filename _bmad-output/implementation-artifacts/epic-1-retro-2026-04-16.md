## What Went Well
1. Story sequencing worked: foundational scaffold first, API health baseline second, orchestration third.
2. Core operational path was established end-to-end (`/api/v1/health`, ordered startup, containerized frontend/backend).
3. Architecture boundaries were largely respected (router/service/schema separation, internal vs external network intent).
4. Review feedback was actively incorporated into Story 1.2 and 1.3 before closure.

## Challenges and Friction
1. Spec drift surfaced in Story 1.3 (`biomistral:7b` vs `mistral:7b`) and required explicit reconciliation with architecture direction.
2. Docker/network correctness issues were discovered in review (internal network flag, healthcheck semantics, missing backend dockerignore).
3. Some completion claims were stronger than supporting evidence (GPU-dependent smoke behavior could not be validated in this environment).
4. Linting and container hardening concerns were deferred and remain visible debt.

## Cross-Story Patterns Observed
- **Review-driven quality uplift:** multiple issues were caught during review rather than during first-pass implementation.
- **Infrastructure assumptions needed tighter verification:** healthcheck details and startup gating required careful refinement.
- **Documentation generally strong, but occasional checklist mismatch:** task checklist accuracy needs stricter alignment to actual edits.

## Technical Debt and Deferred Work
1. `backend` and `frontend` containers run as root (deferred).
2. Missing `frontend` healthcheck in `docker-compose.yml` (deferred).
3. Next.js `NEXT_PUBLIC_API_URL` hardcoded fallback approach (deferred).
4. Frontend lint command targeting should be tightened when CI linting is finalized (deferred from earlier review).
